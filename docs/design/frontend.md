# Frontend

_The SPA's views, components, and conventions._

**Frontend** is an eight-view SPA (vue-router: `/positions`, `/positions/:id`, `/transactions`, `/reports`, `/research`, `/users`, `/account`, `/login`) plus the shared `components/PaginationBar.vue`, `components/SplitWarnings.vue` and `components/SavingsPlans.vue`. `/reports` (nav label **Reports**) picks a period with year chips plus two date fields and renders **three** sections under it, each one block per currency: the book's own history as a chart, then what was realized, then "If you had never sold". They share the picker, though not on the same terms — the two reports below are filtered by which *trades* fall in the period, while the chart's bounds select which *sessions* are drawn and never change what is folded.

`components/EquityCurveChart.vue` draws inline SVG; there is no chart library, and the scaling arithmetic lives in `curveMath.ts` so it can be unit-tested without a DOM. The chart has two modes rather than two lines on one axis: **Value** plots market value against money paid in, which share a scale because they are the same unit and the gap between them is the gain, and **Performance** plots the contribution-free index. The benchmark joins whichever mode is showing and belongs on the same axis in both — its value is the same money in a different holding, and its index is the same notional 100. What the two modes exist to keep apart is money against an index, not a book against a benchmark. Drawing an index around 100 on the same axis as a market value in the millions would imply a relationship that is not there. Money is anchored at 0 so a small wobble is not rendered as a cliff, and the index is anchored at 100 so "did this beat standing still" is always on screen. **A maximum drawdown is a depth, not a movement**, so it renders through `formatBpsMagnitudeOrUnknown` — the signed formatter prints the worst fall a book ever took as `+15.99%`, which reads as a gain. The **Sync prices** button sits beside the chart rather than with the quote refresh on Holdings, because an empty chart is where a user goes looking for it. The ledger carries the realized numbers per row, showing an em dash on a buy rather than `$0.00`. The annualized return sits on `/positions` instead, as a fifth card in each currency block — it is measured since inception, so a period picker would falsely appear to filter it, and its closing figure is the market value that page already shows. `/positions` also carries the **allocation** block under each currency's cards, and its symbols link through to `/positions/:id` — the holding's own page, which is where that holding's entries, its own rate of return and its onward link to the research feed all live. Closed holdings link too: once a position is sold, its entries and what it banked are exactly what a reader is after. Split warnings sit above everything on that page rather than inside a currency block, because what they say is that the figures below them are wrong, and a reader scanning the cards has to meet the warning before they believe one. `/research` (nav label **Research**) is the merged headline feed over the caller's open holdings with a per-company figures panel under it; its arithmetic lives in the unit-tested `fundamentalsMath.ts` and `newsTime.ts`, which renders a headline's age relative for the first day and as the **UTC date** after it — deliberately not the reader's locale, for the same reason the ledger slices its own dates. `frontend/src/types.ts` mirrors the Go models and is the contract between the two halves — keep it in sync when changing JSON shapes. `api/client.ts` is the only place that talks HTTP; views call `instrumentApi` / `transactionApi` / `positionApi` and hold their own local state. **There is no instruments page, and no separate add step.** An instrument only exists to be traded, so `components/InstrumentPicker.vue` — the trade form's instrument field — *is* the search: typing filters what has already been traded (client-side, instant, since trading the same handful of stocks repeatedly is the common case) and, after a 400 ms pause, queries the provider for the rest. Choosing a result that is not on file yet creates it on the way through, which is invisible apart from the form filling in. Making that a second explicit action would turn picking a stock into managing master data. Quote refreshing lives on `/positions`, where the numbers it feeds are shown. `instrumentApi.rename` and `.remove` have no UI; they remain callable admin-only endpoints (module-level refs, no Pinia). `/account` carries two independent forms — the password change and the brokerage fee table — each with its own error and success state, since one page-wide message would let a save on either look like a save on both. The savings-plan table is on the Ledger page, beside the prompts it raises. `session.ts` is the dependency-free source of truth for the bearer token and current user, mirrored to `localStorage` and exposed as reactive `isAuthenticated`/`isAdmin`; `api/client.ts` attaches the token to every request and calls `clearSession()` on any 401. The router guard mirrors the backend's rules as a convenience — the API enforces them.

Each view follows the same shape: `load()` / `changePage()` / `applyFilter()` plus `loading`/`error`/`success` refs, with `applyFilter` resetting `offset` to 0 and `load` stepping back a page if a deletion emptied the current one.
